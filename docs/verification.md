## 直播合并接口

- 离线验证：`tests/live-playlist.test.mjs` 覆盖分组、去重、列表名特殊字符、相对地址补全、非播放列表内容识别与 token 校验；`cloud/test_deploy_service.py` 用模拟 gcloud 覆盖请求日志排除规则的新增、保持与更新，真实项目上的执行见下文。另在本机用替身配置直接调用路由与中间件，实时下载 6 个示例列表得到 505 条、30 个分组，并确认：token 错误返回 404；单个列表失败时沿用其上次成功的副本；全部不可达或超过 5 MB 时返回 502；没有启用的列表时返回空列表；中间件只放行该路径；列表地址跳转后按最终地址补全相对地址，返回维护页时沿用上次有效副本。`tsc --noEmit` 与相关文件 eslint 通过。增量导入的直播部分只经过 `cloud/test_add_sources.py` 的模拟接口测试。
- 2026-10-24 部署：`secrets.py` 生成 `lunatv-live-token`；部署前确认费用保护没有暂停服务，随后 `deploy_service.py` 构建并部署；`--add-sources` 只补充 5 个 iptv-org 直播列表，原有点播源和其他设置未改。部署后服务级实例上限仍为 1，`DISABLE_VIDEO_PROXY` 与 `DISABLE_BACKGROUND_JOBS` 保持开启，运行容器挂载 4 个秘密。
- 现网检查：合并地址返回 200，共 504 条、30 个分组，包含 5 个 iptv-org 分组，内容不含 token；缺少或错误的 token 返回 404；匿名搜索与 `/api/live/sources` 返回 401；媒体代理与 cron 返回 403。
- 日志排除：`lunatv-live-playlist` 规则加上后几分钟才生效，期间 3 条验证请求被记录，其中 1 条带有首个 token。随后添加新 token 版本、停用旧版本并生成新修订；规则生效后的探测请求不再出现在日志中。
- 投影仪：通过 OrionTV 远程输入把直播源地址改为合并地址并保存（token 中的 `_` 以 `%5F` 发送）。直播页自动播放 CCTV-1，频道列表显示 Guovin 分组和 5 个 iptv-org 分组；用户确认 AXN Asia Taiwan 可以播放。其他频道（包括限台湾播放的频道）未逐一实测。
